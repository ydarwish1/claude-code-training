## Description

Three merchants have reported that the dashboard's daily volume does not match their settlement statement.

Two of them are off by a few cents on high-volume days. The third, a merchant in Berlin, sees an entire day of volume attributed to the wrong date.

Support has not been able to reproduce it reliably, and the pattern is not obvious from the tickets. We do not know yet whether these are one bug or several.

## What we know

- The Berlin merchant is the only reporter outside North America.
- The discrepancy grows with transaction count, which suggests accumulation rather than a single bad record.
- One merchant with heavy refund activity reports totals that look **too high**, not too low.
- Nobody has checked whether the payouts screen agrees with the payments screen.

## Found during NWP-101

Two defects in the same area, found while building the payments export and
deliberately not fixed there. Both reach the export, because it reuses
`sortPayments`.

- **Amount sorting is lexicographic, not numeric.** `sortPayments` in
  `src/data/queries.ts` compares amounts with
  `String(a.amount).localeCompare(String(b.amount))`. Measured against the
  running server, `?sort=amount&direction=asc` returns `10.00, 100.04, 100.41,
  100.43, 100.43, 100.59` in three different currencies — minor units
  `1000, 10004, 10041, 10043, 10043, 10059` in string order. So `$1,234.00`
  sorts before `$99.00`. The comment above that line used to claim the order
  matched the table, which is how it stayed hidden.
- **The same sort ranks currencies against each other.** Even with a numeric
  compare, it would still order raw minor units across USD, EUR and GBP with no
  conversion, so a mixed-currency page sorts by a number that means three
  different things. That is the standards doc's item #3, not just item #2.

## What we need first

A written diagnosis before anyone edits code: which files are involved, what the root cause is for each symptom, and which of the three reports share a cause.

Do not fix it in the same session that finds it. Read first.
